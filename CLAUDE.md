# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Meeting Copilot: a local app for Milan that listens to meetings, transcribes them on-device, and drafts answers in Milan's voice when someone asks him something. Answers draw on an Obsidian knowledge base built from past meetings. The dashboard is a React app in `web/` (Vite, plain JSX + CSS, no other deps), built to `web/dist/` and served at http://localhost:8000. If `web/dist` is missing, `/` falls back to the old vanilla page `static/index.html`, which stays reachable at `/classic`.

## Commands

```bash
.venv/bin/pip install -r requirements.txt                 # setup (Apple Silicon: mlx-whisper)
cd web && npm install && npm run build                    # build the UI (rebuild after editing web/src; `npm run dev` = hot reload on :5173; `npm test` = node tests for format.js)
cp .env.example .env                                      # needs ANTHROPIC_API_KEY and/or OPENAI_API_KEY, or copilot.py exits
.venv/bin/python copilot.py                               # listen on default mic
.venv/bin/python copilot.py --device "Teams" | --list-devices | --watch file.txt | --no-audio | --port N
.venv/bin/python kb.py import-sessions | compile [ID] | index | lint [--fix] | weekly [DATE]
.venv/bin/python kb.py backup | dedupe [--apply] | merge FROM TO | rebuild-pages [--all] [PAGE…] | find QUERY | threads
```

Tests: `.venv/bin/pip install -r requirements-dev.txt` once, then `.venv/bin/python -m pytest`. `tests/conftest.py` sets `SESSIONS_DIR`/`VAULT_DIR` to a temp dir before import, stubs `llm.complete` (the `stub_llm` fixture records every prompt and fills replies from the schema), and the `app` fixture runs the FastAPI app with no audio and a fresh `Meeting`. Lines land on the app's loop, so use `wait_for`. There is no linter. To try the pipeline by hand without audio or spending tokens, do the same: run with `--no-audio`, stub `llm.complete`, temp `VAULT_DIR` and `SESSIONS_DIR`. Then push lines with `curl -X POST localhost:8000/segment -H 'Content-Type: application/json' -d '{"text":"..."}'`.

## Architecture

Modules: `config.py` (all env settings) · `llm.py` (provider dispatch + usage tally) · `audio.py` (mic + speech-to-text) · `voice.py` (who is speaking) · `speakers.py` (how speaker labels are written, parsed and explained: the only place that knows `Milan:`/`Other:`; the UI mirror is `speakerName`/`speakerChip` in `web/src/format.js`) · `triggers.py` (when to answer) · `pages.py` (wiki page paths, frontmatter, `read`/`edit` a page; list-valued keys are encoded only in `pages.LISTS`) · `meeting_notes.py` (the one place that knows a Meeting note's layout: `load`/`write`/`exists`/`mark_for_recompile`/`needing_recompile`/`with_person`/`rename_person`; layout pinned by `tests/test_meeting_notes.py`) · `kb.py` (vault + CLI; re-exports `RAW`/`WIKI`/`split_frontmatter`… from `pages`) · `copilot.py` (state, FastAPI, SSE, main).

**The core design goal is few LLM calls.** Speech-to-text is local (`mlx-whisper`, `TRANSCRIBE_BACKEND=local`). By default `AUTO_MODE=off` (`meeting.auto`, which can be toggled in Settings): no LLM call happens unless the user clicks. The clicks are Answer or Questions on a transcript line, the composer buttons, Suggest questions, and Refresh notes. Each of those calls sends the whole transcript (`meeting.full_text()`) first in the user message, so consecutive calls share a cached prefix, followed by the relevant wiki pages. Everything below that runs on its own (the funnel, `ask_moment`, topic-change questions, the timers in `summary_loop`, final notes at End meeting) only runs when `meeting.auto` is on.

In auto mode, each new line goes through a three-step funnel:
1. `triggers.rule_check`: free regex rules (name or alias mention with fuzzy match, opinion phrases, "you"-questions; filler like "you know" is stripped first). Strictness comes from `meeting.sensitivity`.
2. `triggers.triage`: the cheap `TRIAGE_MODEL` (Haiku when `ANTHROPIC_API_KEY` is set) confirms the line is for the user and rewrites it as a standalone question. It runs in `copilot.flag_worker`, which collapses a backlog to the newest flag and passes recently answered questions so the same question isn't answered twice.
3. `copilot.answer`: the `MAIN_MODEL` writes the spoken answer.

**Questions to ask** (`suggest_questions`) are a separate step on `QUESTIONS_MODEL` (gpt-5.4, effort medium). They run when `triggers.ask_moment` matches ("any questions?", "moving on"…), when the summary's `current_topic` changes, on the "Suggest questions" button, or after `QUESTIONS_EVERY_S` as a fallback, never more often than `QUESTIONS_COOLDOWN_S`. `/questions` takes an optional `focus` (typed text) or `segment_id`. One call first settles the meeting type (`meeting.meeting_type` from Settings, or inferred into `meeting.detected_type` when it is `auto`) and applies that type's lens from `MEETING_TYPES`, then drafts 6 scored candidates from different `QUESTION_ANGLES` (confirm, edge_case, contract, rollout, priority, connect) and picks 0–2. All lenses live in the cached system prompt (`lenses_text()` fills `@@LENSES@@`, and the schema's `meeting_type` enum is built per call); only the chosen type goes in the user message. Types are user-editable in Settings (POST `/meeting_types` add/update/remove/reset). They are saved to `sessions/meeting_types.json` and default to `DEFAULT_MEETING_TYPES`. That endpoint returns the changed config instead of broadcasting `config`, because the reducer treats a `config` event as a reconnect and resets. Code then drops picks that are already answered, score under 7, or `is_repeat` of an earlier suggestion. When the user asked and nothing survives, the best fresh candidate is shown anyway. The prompt includes `me.md`, relevant wiki pages, and 👍/👎 history from `sessions/question_feedback.jsonl`.

**AI Chat** (`/ask`) uses `CHAT_MODEL` (gpt-5.5, `CHAT_EFFORT` medium) with the transcript, up to 8 wiki pages and the last 8 chat turns (`history`), since the user asks rarely and wants careful answers.

**Weekly review** (`kb.write_weekly`, one `CHAT_MODEL` call per week) reads each meeting's compiled note (or its transcript, capped at 8000 words, when not compiled) plus last week's review, and writes `wiki/weekly/<monday>.md` (to-dos, waiting on, decisions, need to know, to think about, next week). `copilot.weekly_loop` writes it once from `WEEKLY_DAY` (4 = Friday) at `WEEKLY_HOUR` (15), and last week's if it's missing; the Weekly review page (GET/POST `/weekly`, GET `/weekly/{week}`) can write or rewrite any week. SSE kind `weekly` reports writing/ready/failed.

The running summary (`summarize`) runs only on Refresh, plus every `SUMMARY_EVERY_S` and at End meeting in auto mode. Each run sends the transcript since the previous run, plus 60 s of overlap. Keep new features inside this budget.

**Provider dispatch.** `llm.complete(model, system, user, schema=...)` picks Anthropic for `claude-*` model names and OpenAI otherwise. It returns parsed JSON when a schema is given; OpenAI strict schemas require every property to be listed in `required` and `additionalProperties: false`. Put stable content in `system`, since Anthropic caches it explicitly and OpenAI caches the prefix automatically. `copilot.stable_prompt()` adds `me.md` and `index.md` to the system prompt for this reason. Per-call token usage builds up in `llm.usage`, and `broadcast_usage()` pushes it to the UI. The cost readout uses `config.PRICES`, so a new model needs an entry there (or `MODEL_PRICES` in `.env`). Model defaults depend on which API keys are set (see `config.py`).

**Speech detection (`_chunker`).** The background level is the 10th percentile of block RMS over the last 10 s, and speech is anything above `max(2.5 × floor, MIN_SPEECH_RMS)`. Don't go back to averaging "non-speech" blocks into the floor: that feeds back, the threshold climbs above quiet far-field speech within about a minute, and transcription silently stops. To diagnose, read `sessions/<id>/audio_debug.log` (on by default in mic mode; `AUDIO_DEBUG=<file>` overrides the path). Every 5 s it logs levels, threshold, chunk/final/draft counts, queue sizes, `silent_for`, `reconnects` and `busy_for`.

**Mic watchdog.** macOS can stop feeding an `InputStream` without raising an error when the input device changes or disappears. `_watchdog` reopens the stream when no non-zero block has arrived for `MIC_TIMEOUT_S`. It reloads PortAudio's device list first so a new default mic is found. A native whisper/torch call can also hang forever (seen several times in long-running processes), and a Python thread can't be killed. So when one transcription runs longer than `STUCK_S`, `restart_transcriber` bumps `worker`, and a fresh transcriber thread starts with its own models (thread-local `_tls.models`), at most `MAX_RESTARTS` times. The abandoned thread checks `worker` and exits without emitting. `reset_meeting()` calls `transcriber.new_meeting()`, which drops the old meeting's queued chunks and restarts a transcriber stuck for more than 20 s. `audio_debug.log` shows a stall as a `busy_for` that keeps growing and `queue_chunks` piling up, and counts recoveries in `restarts=`. `_keep_alive` restarts the chunker or transcriber thread if it raises, instead of letting it die silently.

**Live transcript.** `AudioTranscriber` has one transcription thread, since MLX models are not shared across threads. Finished chunks always go first (accurate `WHISPER_MODEL`, with a name/context prompt). Don't add recent transcript lines to that prompt (`prompt_hint`). Whisper repeats its prompt back, so one hallucinated line (for example a stray Cantonese particle) gets copied into every following line until it drops out of the prompt. `_local_segments` limits whisper to `temperature=(0.0, 0.5)` and a `sample_len` sized to the audio. The default 6-step fallback ladder measured 6–8 s of full GPU per unclear chunk instead of ~1 s and made the laptop run hot, so don't remove the cap. `clean_text` also strips characters from other scripts when `WHISPER_LANGUAGE=en` and collapses repeated phrases. When no chunk is waiting, it re-reads a snapshot of the unfinished chunk with the small `PARTIAL_MODEL`. Drafts get no prompt, because the small model echoes it, and a token cap so a hallucination loop can't stall them. `gen` counts finished chunks so a stale draft is dropped. Drafts go out as SSE `partial` events and are never stored or checked for questions; the UI swaps the draft for the next `segment`.

**Voice ID (`voice.py`, `voices.py`).** Every distinct voice becomes a remembered Voice with a number that is never reused, and the same number comes back in later meetings. `voice.py` turns audio into an ECAPA print (SpeechBrain, CPU, ~45 ms). `voices.Registry` works only on prints, so it is testable with made-up vectors, and is saved to `sessions/voices.json`. `_transcribe_labeled` labels each whisper segment through `Registry.identify`: `>= VOICE_MATCH` (0.45) against a Voice's print is that Voice; below `VOICE_NEW` (0.35) for every Voice and at least `VOICE_NEW_MIN_S` long is a new Voice; in between, or under 1 s, is unlabeled (short pieces borrow a neighbour's label). The thresholds lean towards a new Voice over mixing two people up, because a split can be fixed by naming and a mix-up can't. A young Voice (fewer than 10 matches) averages its matches into its print, since a one-line print is rough. After that a print only learns once per meeting: `Registry.end_meeting` (run by `copilot.end_voice_meeting` at End meeting, New meeting and shutdown) moves it a bounded step (`LEARN_RATE` 0.1) towards that meeting's confident matches (score ≥ match + 0.1, at least 3), and drops unnamed Voices not heard for 30 days (`speakers.named_numbers()` are kept). Numbers are never reused. `Registry.forget(n)` (POST `/voices/forget`, the Forget voice link on each Speaker card) deletes one print but keeps the number and its name, so past lines still read right; that voice then comes back as a new Speaker N. Without audio the endpoint edits `sessions/voices.json` directly. Settings → Record my voice calls `/voice/enroll`; `AudioTranscriber` routes the next ~20 s of speech to `VoiceID.enroll`, which makes or refreshes the Voice that is Me (`Registry.set_me`). The old single `sessions/voice.npy` is migrated into Me's Voice once and renamed `.migrated`; only the app's own registry migrates, never one passed in. Consecutive same-speaker segments merge into one line. Labels (`speakers.py`): `me` is written `Milan:`, Voice 3 is `s3`, written `Speaker 3:`, the legacy `them` is `Other:`. Transcripts store these and are never edited (`docs/adr/0001`). Every prompt explains them via `speakers.NOTE`, and auto mode never flags the user's own lines. Per-line scores go to `audio_debug.log` (`voice=`) for tuning the thresholds.

**Threads vs event loop.** The audio threads (`AudioTranscriber`) and `watch_file` must only touch state through `add_segment()` / `set_status()`, which hop onto the loop with `call_soon_threadsafe`. `AudioTranscriber` receives callbacks rather than importing `copilot`, to avoid a circular import.

**UI protocol.** `/events` is SSE, with messages `{"kind", "data"}`. Kinds are `config`, `voice` (recording progress), `voices` (named Voices changed: `{s3: {name, me, person}}`), `segment`, `partial`, `questions_pending`, `questions`, `flag` (per-line state: checking/answering/answered/skipped), `answer_pending`, `answer`, `answer_failed`, `analysis`, `status`, `usage`, `kb`, `weekly`, `brief`. A new subscriber is sent the current state again (config, which carries `voices`, then segments, flags, answers, analysis, brief, usage). A new kind needs a case in the reducer in `web/src/useMeeting.js`. A new endpoint path also has to be added to the `api` proxy list in `web/vite.config.js`, or it 404s under `npm run dev` (it works from `web/dist` either way). GET `/meetings` and `/meetings/{id}` serve past meetings from the vault (`kb.list_meetings` / `kb.load_meeting`) for the Meetings page. GET `/people` (`kb.list_people`) feeds the Speaker name box's autocomplete (one `<datalist id="people-names">` in `App.jsx`). The Speakers strip (`Speakers.jsx`, live and past Meetings) is computed in the browser by `format.speakerStats` from the lines it already has, so it needs no endpoint. `/new` ends the current meeting (same as `/end` when it has lines) and swaps in a fresh one via `reset_meeting()`: new `meeting`, `meeting_id`, `session_dir`, cleared usage and flag queue, audio debug log moved to the new folder. Long-running calls capture `m = meeting` and drop their result if a new meeting started meanwhile. POST endpoints: `/new`, `/weekly`, `/brief` (optional `focus`), `/meeting_types`, `/voices/name` (`voice`, `name`), `/voices/forget` (`voice`), `/recompile`, `/voice/enroll`, `/voice/cancel`, `/voice/forget`, `/settings`, `/questions`, `/answer` (segment_id | question, optional `style` shorter/different/detailed), `/ask`, `/feedback`, `/summarize`, `/pause`, `/segment`, `/end`.

**Knowledge base (`kb.py`, `vault/`).** Follows Karpathy's LLM-wiki pattern: no embeddings. The goal is that it gets sharper with each meeting rather than just bigger. `raw/meetings/<id>.md` holds transcripts and is never edited. A meeting counts as compiled when `wiki/meetings/<id>.md` exists. `index.md` is always regenerated by `rebuild_index()`. `vault/CLAUDE.md` holds the vault's own conventions (written only when missing, from `kb.VAULT_RULES`).
- **Page layout.** Entity pages (`people|projects|topics/<slug>`) hold one current picture: `## Now` · `## Key facts` (≤15, cited `([[meetings/<id>]])`) · projects also `## Decisions`, `## Open threads`, `## People` · `## Log` (one dated line per meeting, append-only). `parse_page`/`render_entity` keep that order. Pages in the old layout still have `## Notes`; any rewrite turns those bullets into Log lines (`legacy_log`), so history is never dropped. `lint` reports them as `old_layout`.
- **compile_meeting** is still one call. `compile_candidates` first picks likely pages (`find_pages` + people named in the transcript) and sends their current Now/Key facts/Decisions. For pages it saw in full, the model returns updated lists and `write_entity(replace=True)` swaps them in. Truncated or unseen pages get a duplicate-free merge instead. The same call returns glossary entries, new/closed threads, `me_new` (appended to `wiki/me-log.md`) and `me_learned` (a ≤12-bullet rewrite of me.md's `## Learned from meetings`; prose found there is archived to me-log first). `wiki/me.md` is otherwise hand-edited.
- **Who spoke.** Compile works out, by code and not by the model, who spoke (`transcript_speakers` over the stored labels: Person paths, `me` included, plus the unnamed count) and hands it to `meeting_notes.write`, which records `people:` and `unnamed_speakers:` and a `## Who spoke` line of wikilinks for Obsidian's graph. `MeetingNote.sections` and `.prompt_text` hide that section. `meeting_notes.with_person` (used by the Brief) matches who spoke first, then links for older notes. `merge`/`dedupe` call `meeting_notes.rename_person`.
- **Recompile after naming.** When `name_voice` changes a Voice's Person, `meeting_notes.mark_for_recompile` adds the reason (`needs_recompile: Speaker 3 is now Priya`) to every compiled Meeting note whose Transcript has that Voice (`voice_meetings`). No model call. `meeting_notes.needing_recompile()` lists them; they show as a badge plus a Recompile banner on the Meetings page (POST `/recompile`, one `MAIN_MODEL` call each, only on that click), in `kb.py compile` (`compile_pending(stale=True)`) and in `lint`. End meeting's `compile_pending()` leaves them alone. Rewriting the note clears the mark. On recompile `write_entity` replaces the Log line citing that same meeting in place (the one exception to append-only, stated in `VAULT_RULES`), and me-log facts already logged for that meeting aren't added again. Moving a Voice from one Person to another also `flag_review`s the old Person's page (`needs_review` / `review_meetings` frontmatter); `lint` reports the lines there citing the affected meetings under `check_after_voice_moved` and never deletes them. The user clears the two frontmatter lines after checking.
- **Glossary** (`wiki/glossary.md`, `load_glossary`/`merge_glossary`/`alias_map`): canonical names plus aliases and mis-hearings. It is used in compile (canonical paths), lookup (alias expansion), `copilot.stable_prompt` (cached) and `copilot.prompt_hint` (names only, through `hint_terms`).
- **Voices** (`wiki/voices.md`, `voice_people`/`name_voice`/`person_for`): `- Speaker 3 → [[people/priya|Priya]]`, with `[[me]]` for the user. Naming a Voice writes this page and creates the Person page if needed; several Voices can point at one Person. It is re-read whenever its mtime changes, so Obsidian edits count. kb installs it into `speakers.use_people`, so `speakers.display`/`render_line`/`render` show names when text is read (`Meeting.full_text`, compile, weekly), while `format_line` and stored Transcripts keep `Speaker 3:` (ADR 0001). A Voice named as the user counts as Me (`speakers.is_me`) and its future lines are written `Milan:`.
- **Threads** (`wiki/threads.md`): `- [ ] t7 · owner → waiting on · item · [[project]] · since [[meeting]]`. The user can tick boxes in Obsidian. `save_threads` copies open items into each project's `## Open threads`. The weekly review reads them.
- **Lookup.** `find_pages` (behind `relevant_pages`) runs BM25 over title/summary/aliases/current sections (not Log), cached until a wiki file's mtime changes. It boosts pages named in the query (or in `context`) and prefers entity pages over meeting notes.
- **Maintenance.** All of these run `backup()` to `vault/.backup/<time>/` first. `dedupe` (one `CHAT_MODEL` call, dry run unless `--apply`) and `merge` fold duplicates and fix every link. `rebuild-pages` converts old-layout pages (one `MAIN_MODEL` call each) and condenses me.md.
- **Brief** (`copilot.write_brief`, POST `/brief`, SSE kind `brief`, `meeting.brief`) is one `MAIN_MODEL` call. It reads `find_pages` hits, `related_threads` and `meeting_notes.with_person` (the last meeting with the same people), which means the People whose Voices have spoken so far when there are any, else people mentioned. It runs on the "Brief me" button, and in auto mode once, 8 s after the meeting description stops changing.

**Session files.** `sessions/<id>/` holds `transcript.txt`, `summary.md`, `answers.md`, `questions.md` and `feedback.jsonl`. `sessions/` and `vault/` hold personal meeting data and are gitignored. On shutdown or End meeting, the transcript is also saved to `vault/raw/meetings/`.
